# Screen Color desktop app

## Intent and decisions
Peter approved moving from the successful color experiment to the actual app on 16 November 2026: "Enough with the tests lets now build the actual app. Its a great direction." He requested Electron development with live UI updates. His reference is a Samsung A52 4G in Vivid mode, neutral white-balance slider, compared with an HP ProBook 450 G4 / Intel HD 620. The goal is preferred color richness, not measured calibration or OLED hardware emulation. Purple character skin, green eyes/trail and orange weapon highlights are his comparison landmarks.

Working name **Screen Color** is the builder's call; branding can change. First delivery is a Windows development app with no installer, production packaging, push or release. Work in this new independent repository on `dev`, commit verified work locally. Reuse an installed Electron runtime; do not download dependencies. Initial implementation is plain HTML/CSS/JavaScript with Electron, a Node development server, and an x64 C# helper built using the installed .NET Framework compiler. These are builder choices for a small dependency-free local app.

## Version one
- Keep the proven Magnification fullscreen RGB color matrix. Saturation 0–200%, contrast 80–140%, warmth -300 to +300; original numeric strengths remain unchanged. Add software brightness 80–120% and tint -100 to +100 using bounded channel gains. Label brightness as software dimming/brightening, not backlight control. Neutral: 100/100/0/100/0 respectively. Peter reference: saturation 139, contrast 115, warmth 100, brightness 100, tint 0.
- Controls update the actual desktop while dragging, with exact numeric inputs and per-control reset. Effect stays on until toggled off or the app quits; there is no mandatory 60-second timer. Optional timed preview (60 seconds) restores the prior enabled state rather than erasing the chosen sliders. First run starts off; chosen settings persist across launches. An explicitly enabled effect can resume on later launches after helper readiness.
- Original/adjusted toggle, Reset all, named local profiles (save, select, delete user profiles), protected Neutral and Peter reference presets. JSON versioned settings are validated on read/write, written atomically; invalid files fall back safely with a visible message. Last used profile and unsaved changes have honest UI state.
- Windows tray with show, effect toggle, presets, and quit. Closing the window minimizes to tray while effect remains; explicit Quit restores the captured baseline and ends the helper. Global Ctrl+Alt+F12 disables the effect if registration succeeds; UI and tray always work when unavailable.
- Optional Windows sign-in startup, off by default. Toggle changes the current user's registration only on their action, with readback. Startup launches the existing Electron executable with this app's absolute directory and --background, without requiring a development server. Development startup is tied to current source/runtime locations and must say so in Settings.
- Native helper captures the existing matrix, accepts validated line-delimited JSON commands, applies verified readback, restores on stdin EOF/quit. A recovery child restores the captured baseline if the helper dies. Helper monitors its Electron parent, and refuses another instance for the same user/session. It also refuses to run alongside the existing ColorTest experiments: show a clear close-the-experiment message.
- Display changes/resume trigger a bounded reapply only while enabled. No repeated forced resetting that fights other tools. Version one is explicitly **all displays together**; UI must not imply per-display control. List connected displays for context. Independent per-monitor correction, HDR processing, gamma, nonlinear shadow/highlight curves, selective vibrance, DDC brightness and application automation are deferred. Do not ship nonfunctional sliders for these.
- Disable processing when a helper failure occurs, show an actionable error and offer retry. Don't show "Applied" until native acknowledgment. Coalesce slider traffic, serialize mutations, and prevent stale responses or failed writes from lying about persisted/effective settings.

## User interface
Operate mode: a compact dark Windows utility, warm amber accent, neutral graphite surfaces and Segoe UI Variable / Segoe UI. Controls left, a quiet calibration/preset area right; Settings is a separate view inside the same window. Clear effect status and toggle remain visible. Color swatches and grayscale ramp are test content, not claims about physical panel output. No remote fonts, assets or telemetry. Keyboard accessible labeled controls and visible focus. At narrower sizes stack columns and preserve access to all actions. Minimum Electron window 760×620; initial 1020×760. The layout is a builder call, not a user-approved mockup.

Renderer is sandboxed, context isolated, node integration off, restrictive CSP, narrow preload methods; validate IPC sender and payloads. No arbitrary file/command access. Development localhost HTTP preview exposes UI only, not a writable control API. Browser preview must state that desktop controls require the Electron app. Electron loads local files so sign-in startup works offline. Main/preload edits need app restart; renderer edits reload live without restarting native processing.

## Verification and handoff
Use Node built-in tests for validation, matrix math, persistence, state transitions, timer behavior and helper transport. Native check captures baseline, sets a small transform, checks readback, restores and checks baseline. Avoid running native checks concurrently with the user's experiment. Exercise Electron via CDP or a local smoke mode for renderer errors, preload bridge, native connect, profiles and reset; inspect screenshot. Verify server on a localhost URL, clean git state, and document environment limits rather than claiming physical quality or sign-in testing not performed. Archive significant before/after UI evidence centrally; keep captures missing if unavailable, never fabricate them.

## Acceptance
Peter can close the old experiment, double-click the launch script, adjust the desktop live, save and recover his reference, leave the app in the tray without timeout, quit and recover baseline, and opt into startup. Development renderer changes appear without regenerating the native executable. No new dependency download or production build is needed.
